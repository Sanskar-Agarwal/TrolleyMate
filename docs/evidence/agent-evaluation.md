## Limitations

| Area | Limitation |
|---|---|
| Offline knowledge | In offline mode the rule-based judge knows only its listed term/restriction pairs and the 21 FSANZ notes. Any other vague term is judged 'none' at 0.97 and clears (T04). A live model covers the rest, and fallback answers never clear a term (T08, T09). |
| Unknown restrictions | A restriction with no rule makes every product uncertain (P11), so the whole basket is withheld with one review case per item. It's safe, but it floods the review queue. Intake should refuse ids outside the vocabulary: extract_constraints is told to use only known ids, but form patches aren't checked (Sanskar). |
| Safety lock scope | UC-06's failure scenario describes a lock on the whole basket. The code withholds only the product with the corrupt record (P10). Still to confirm with Maaz. |
| Re-verification of a built basket | POST /baskets/{id}/verify, which is API only with no UI caller, flags a newly unsafe product as a violation and blocks acceptance (S14). But it leaves the product in the basket and its total, and labels the basket 'verified'. A FAIL verdict also requests no review for any uncertain item beside it, which stays withheld until the basket is rebuilt (7.4/9.4: FAIL ends the automated lifecycle). |
| Chat-edit extras | A pantry or snack extra that no longer passes is dropped with a message (S07, S08), not held for review. This matches how a chat 'add' already refuses uncertain products. |
| Prompt injection | Label text goes into the assess_ingredient prompt verbatim, and a confident 'none' (0.95 or above) from the live model clears the term. Defences: the output contract (T07), the threshold (T05) and the FSANZ notes. Dietitian review covers only items already uncertain. |
| Knowledge base | Oats aren't tagged gluten, though FSANZ treats them as a gluten cereal. The spices note covers milk but not lactose. Animal rennet isn't in the vegetarian rule (the KAN-19 strict xfail). The label backstop (P08) only catches allergens a label names, so Pearl Barley still needed its data fix (P12). |
| Degraded mode cost | Fallback answers aren't kept across requests (T11). During an outage, each request retries the live model once per vague term, up to LLM_TIMEOUT_S each. Safe, but slow. A circuit breaker in LLMService would help (Maaz). |
| Learned dislikes | The learn_preference line no longer names the product (S13). The 'Declined: A → B' substitution line beside it still does, so a forgotten learned dislike is still visible in the substitution log. |
| Open points carried from KAN-22 | substitution.propose still ignores dislikes. A multi-word dislike matches on any word (catalogue.disliked_by). The likes nudge (about 8%) changes Balanced baskets only. _refresh_nutrition fails if Requirements gains a field without a default. |
| Scripted tools | Model replies and outages are scripted, so the run is repeatable. These are not a live model's own failures. A run against the Campus Qwen model is still to do. |
