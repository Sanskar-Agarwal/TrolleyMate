## Defects corrected during UAT

1. **Groq output reservation:** an initial explanation exceeded the free-tier output reservation.
   Requests now cap output at 768 tokens and use instruct mode for the configured Groq Qwen
   model. Truncated/empty responses fail safely. These settings do not increase provider quota.
2. **Financial claims:** model text quoted a $2.22 saving where computed values gave $2.21.
   Price insight now receives computed deltas and rejects financial figures outside the
   grounded values, falling back to deterministic text.
3. **Acceptance explanation:** a model said a basket was ready despite a nutrition gap.
   Withheld items and inadequate nutrition now force a grounded explanation of the blockers.
4. **Meal counts:** adult-equivalent portions appeared as the number of meals in a negotiated
   plan. UI and negotiation now use the explicit household meal schedule.
5. **Audit privacy:** intake `raw_text` remained visible despite prompt/raw redaction. It is
   now redacted in stored and legacy record views where preference memory is disabled.

## Requested security controls

Full design and configurable defaults: [SECURITY.md](SECURITY.md).

- Passwords are salted PBKDF2-HMAC-SHA256 hashes with 600,000 iterations; legacy hashes
  upgrade on successful login. Passwords are not reversibly encrypted.
- Writes require a custom verification header and trusted browser origin, with JSON content
  checks. Authentication remains explicit bearer-header based; cookies are not used.
- Shared SQLite request windows enforce per-IP API/auth/registration limits and per-account
  login/write limits. Throttling returns HTTP 429 and `Retry-After`.
- Random opaque session tokens are stored only as digests on the server and in browser
  `sessionStorage` on the client. Three concurrent logins, 30-minute idle and eight-hour
  absolute expiry are enforced server-side. Sign-out revokes one session; sign-out everywhere
  revokes all sessions for that account. Both remain available under the account-write limit.

|---|---|
| Upgrade | Browser with an old token returned to sign-in; successful new login worked. |

| Throttling | Repeated incorrect logins visibly showed “Too many requests” with retry timing; login worked after the window elapsed. |
| Password storage/migration | Automated fresh-salt, version, malformed-hash and legacy-upgrade tests passed. |
| CSRF | Automated missing-header, hostile Origin/Referer/Fetch Metadata, non-JSON and DELETE tests passed; allowed same-origin/development requests and preflight passed. |
| Session expiry and revocation | Automated idle/absolute expiry, activity without extending absolute expiry, digest-only storage and account-scoped revocation tests passed. |
| Counter concurrency | Automated simultaneous request counting and expired-window reset passed. |
| Browser token handling | Frontend tests cover retirement of persistent tokens, session storage, request header, 401 clearing and 429 preservation. |

The rate counter database is separate from application transactions, so rate-limit updates
do not wait for an in-flight basket write. Session activity writes are coalesced to once per
minute. This was checked by cancelling a build after installing the security controls.

## Provider limits and remaining boundaries

At the first live-flow checkpoint, persisted audit records showed **53 live model decisions
and three provider fallbacks**: one early output-budget failure and two later ingredient calls
that hit the free quota. More successful live calls followed in the secured shopping flow.
Quota fallbacks were labelled and uncertain ingredient data remained held for review.
This is live-provider evidence, not a claim that all calls succeeded or that quotas are fixed.

The browser checks used seeded retailer data and simulated human review, not live purchasing
or real clinical certification. Docker and hosted CI were not rerun for this follow-up; prior
results remain historical. There is no Makefile in this repository; the documented local
Python/npm checks were used. No wholly untouched feature was added during this pass.
Human rehearsal/release sign-off, retrospective, exported Jira/burndown evidence, contribution
agreement and final archive upload remain team tasks, not outcomes established by these tests.
